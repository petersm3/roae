# DOC_GATE_SELFTEST_INSTRUMENTS.txt — every function defined inside doc_gates.sh's
# --selftest region, and the assertion that proves it. Consumed by doc_gates.sh GATE 15.
#
# WHY THIS FILE EXISTS. `_selftest_revert` shipped at fbdbe26 with no fire-proof, in the one
# file whose own header records GATE 8 shipping a one-directional comparison behind a
# hand-taken proof. It was caught only because someone checked a commit message's claim
# against a run. That is the THIRD instance of one class — GATE 8's hand-taken proof, GATE
# 4b's shared dispatch, and now this — so the answer is not more care. A new instrument in
# the harness must now be DECLARED here, naming the assertion that proves it, or GATE 15
# fails.
#
# FORMAT: `function<TAB>proof-label<TAB>note`, one per line. `#` comments and blank lines
# ignored. Must end with a newline (the support-file preflight enforces that).
#   proof-label = a literal string that must occur in scripts/doc_gates.sh — normally the
#                 label of the assertion that exercises the function.
#   proof-label = NOT-PROVEN-IN-HARNESS for a function that genuinely cannot be asserted
#                 from inside a live self-test. The note must then say why and where the
#                 external proof is recorded. GATE 15 prints these every run; they are
#                 declared gaps, never silence.
#
# WHAT GATE 15 CANNOT SEE, stated rather than implied — this is the load-bearing caveat and
# it should be read before trusting a green run:
#   (1) It checks that the function EXISTS and that the named label EXISTS. It CANNOT check
#       that the named assertion actually exercises the function. A row pointing at a real
#       but unrelated label passes. This is bookkeeping with a spell-check, not a coverage
#       prover, and calling it more than that would be the false clear it was written to
#       prevent.
#       THE BLIND SPOT IS NOT EMPTY — MEASURED 2026-08-02 (round 8, item A3), row by row,
#       because "d7 was unclassified for weeks and was found only because it was named".
#       Of the 10 rows: 1 declared unprovable; 5 proven BY INVOCATION (the label is the
#       first quoted argument of a call to the declared function itself — assert_fires_why,
#       assert_stays_clean_why, assert_gen_fires, assert_gen_clean, assert_gen_fires_only);
#       3 proven BY A BLOCK that calls the function and echoes the label a line or two later
#       (_selftest_revert, _g13, _gsrc); and 1 MISDECLARED — scratch_appendonly, fixed in
#       the row below. So the surface is 10 rows and the defect rate on it was 1 in 9.
#       WHAT THAT MEASUREMENT SAYS TO ANYONE BUILDING THE STRONGER FORM: the cheap
#       mechanical rule ("the label must be the declared function's own call-site label")
#       would have caught this instance, but it would ALSO flag those 3 block-proven rows,
#       which are legitimate. So the rule cannot ship as a blanket FAIL on the current
#       corpus, and the honest options are a call-graph/`bash -x` reachability check (item
#       A3's own suggestion) or a declared proof-KIND per row. Measured, not guessed —
#       the same discipline that rejected a coverage-ratio floor for GATE 4b.
#       WHAT THIS AUDIT CANNOT SEE: it was taken by hand, by reading each label's context.
#       It would not catch a row whose label sits in a block that LOOKS like it calls the
#       function but reaches it only on a branch that never runs. Nothing here re-runs.
#   (2) It covers the --selftest region only. Helper functions in gate bodies (check_pair
#       inside gate_cli, the _norm/_cmp family inside assert_gen_fires) are out of scope:
#       they are gate implementation, and the gates have their own fire-proofs.
#   (1a) The label search is over the WHOLE of doc_gates.sh, so a label that occurs only in
#       a comment, or only inside another assertion's mutation string, satisfies it. Not
#       hypothetical: GATE 15's own "a row naming an assertion nobody wrote" fire-proof
#       FAILED on its first harness run because the literal it injected was thereby written
#       into doc_gates.sh, and the fire-proof satisfied the condition it was testing for.
#       It now assembles its substitute label from fragments and asserts the assembled form
#       is absent before injecting.
#   (3) It cannot tell a good proof from a weak one. `assert_fires_why`'s anchor-moved
#       branch is exercised by nothing; the row says so in prose that no machine reads.
#   (4) A row's PROSE is not read by anything, only its key and its label. The `_gsrc` row
#       named a function deleted by a rename for a whole round and this gate was silent;
#       the `assert_fires` row (deleted 2026-08-02, round 8, with the helper) said
#       "Exercised by four callers" while six called it. THE SAME ERROR WAS LIVE IN THE ROW
#       BELOW IT on the same day — `assert_stays_clean` said "Four negative controls depend
#       on it" with six callers at `scripts/doc_gates.sh` (counted, not remembered). So this
#       caveat has three instances, two of them the identical off-by-two in adjacent rows,
#       which is the strongest available argument that the prose column is decoration until
#       something reads it. Treat every note here as a claim to re-verify, not a measurement.
#   (4a) THE OBVIOUS MECHANICAL FORM IS WRONG, AND THE ROW THAT MOTIVATED IT IS THE PROOF
#       (measured 2026-08-02, round 9, drain-1). Round 8 filed caveat (4) with the reasoning
#       that "a caller count is a grep", so unlike the prose-vs-diff class it needs no design
#       pass. MEASURED, that is false in both directions:
#
#       (i) A GREP IS NOT ONE NUMBER. Three defensible counting rules disagree on 4 of the 10
#           rows. Counting the name in COMMAND POSITION at line start gives assert_fires_why
#           57, assert_stays_clean_why 6, _gsrc 0 and _g13 0 — the last two are wrong, because
#           both are only ever called inside `$(...)`. Counting the name as a WORD followed by
#           space/tab/`;` on non-comment lines gives 61, 9, 5 and 4 — the first two are now
#           wrong, because heredocs, `echo` strings and python mutation blobs mention these
#           names constantly and none of those is a call. Hand-adjudicated call sites:
#             _selftest_revert 20   _selftest_release 3 (traps)   assert_fires_why 57
#             assert_stays_clean_why 7   scratch_appendonly 2   _g13 4
#             assert_gen_fires 4   assert_gen_clean 1   assert_gen_fires_only 2   _gsrc 5
#           Distinguishing the three requires a shell parse, not a grep. (The inbox's own
#           "56 assert_fires_why invocations" is a fourth number; it is rule-dependent too.)
#
#       (ii) THE NUMBER THE PROSE STATES IS NOT THE CALLER COUNT. `assert_stays_clean_why`
#           says "SIX negative controls depend on it". It has SEVEN call sites — 2326, 2361,
#           2412, 3019, 3630, 3803 are the six negative controls, and 2444 is the `_asc_probe`
#           PROBE, deliberately expected to FAIL, which the same note names two sentences
#           later. So the prose is CORRECT and a caller-count gate would have gone red on the
#           one row it was designed around. `assert_gen_fires` ("Four legs") and
#           scratch_appendonly ("two scratch legs") are the same shape: a semantic subset of
#           the call sites, which no count computes.
#
#       WHAT THIS LEAVES BUILDABLE, and it is smaller than caveat (4) implies: a row could
#       carry an explicit machine-readable `callers=N` claim, checked against ONE rule stated
#       in this file, with the prose left to say what the N of them ARE. That is a format
#       change to the table and it is the same decision as caveat (1)'s option (b), the
#       declared proof-KIND column — so it should be taken ONCE for both, not twice. NOT
#       shipped here: an instrument measured to contradict its own motivating row is the
#       false clear this file exists to refuse.
